## Evaluation Criteria

### Code Quality
- **Documentation**: README, API docs, code comments
- **Test Coverage**: Unit tests, integration tests
- **Code Organization**: Clear structure, modular design
- **Best Practices**: Follows language conventions, type hints, etc.

### Activity & Maintenance
- **Last Commit**: How recently updated?
- **Stars/Forks**: Community interest indicator
- **Issues**: How are issues handled?
- **Contributors**: Active development community?
- **Releases**: Regular versioned releases?

### Architecture Patterns
- **Design Patterns**: Applicable to HERMES?
- **Agent Patterns**: Coordination, communication, state management
- **Data Flow**: How data moves through system
- **Scalability**: How system handles growth
- **Error Handling**: Robust error management

### Reusable Components
- **Modules**: Can we extract and reuse?
- **Utilities**: Helper functions and tools
- **Abstractions**: Useful interfaces and base classes
- **Integrations**: Third-party service connections

### License Compatibility
- **License Type**: MIT, Apache 2.0, GPL, etc.
- **Compatibility**: Works with our MIT license?
- **Attribution**: What credit is required?
- **Restrictions**: Any usage limitations?

## Documentation Process

For each repository:

1. **Discovery**: Add to priority list above with basic info
2. **Initial Triage**: Quick review of README and code structure
3. **Create Evaluation**: Use `TEMPLATE_repo_evaluation.md`
4. **Deep Analysis**: Review architecture, code quality, patterns
5. **Extract Value**: Identify learnings or reusable components
6. **Documentation**: Complete evaluation document
7. **Decision**: Mark status (Learn From/Integrate/Skip)
8. **Update Log**: Add entry to `../EXPLORATION_LOG.md`
9. **Update State**: Increment counter in `../STATE.yaml`

## Evaluation Files

Create individual evaluation files in this directory:
- `[repo_name]_evaluation.md`
- Example: `awesome_quant_evaluation.md`
- Example: `trading_framework_xyz_evaluation.md`

Use the template: `TEMPLATE_repo_evaluation.md`

## Notes

### Repository Selection Strategy
1. Start with awesome lists for curated high-quality repos
2. Look for production-ready systems, not just academic code
3. Prioritize active projects with recent commits
4. Focus on Python-based projects for consistency
5. Consider architecture patterns over specific features
6. Look for well-documented, tested code

### Analysis Approach
- Clone repo and explore code structure
- Read documentation and understand purpose
- Identify architectural patterns
- Extract reusable abstractions
- Note integration challenges
- Document learnings

### Integration Planning
- Assess effort to integrate components
- Identify dependencies and conflicts
- Consider maintenance burden
- Plan adaptation to HERMES architecture
- Document integration approach
